# RPGraph Continuation Handoff — image.generate on staged-workflow-v1

## Status: Done

Closes the last structural gap in the S10 model-authorable family rollout. `image.generate` was already an advertised, executor-backed staged recipe (since the S6 era) — it just had no working runner behind it in staged mode, since the real ComfyUI generation logic lived entirely inside `executeGraph.ts`'s closure and was only ever published via a callback (`onImageRunnerReady`) fired from inside a graph run. Staged mode never calls `executeGraph` (it calls `runLiveStagedTurn` instead), so the runner variable stayed `undefined` for the whole staged turn.

## What changed

1. **[src/graph/comfyImageRunner.ts](../../src/graph/comfyImageRunner.ts) (new file):** the entire `createComfyImageForCharacter` closure from `executeGraph.ts` — phone-owner/LoRA-character resolution (by name or id), the real `window.rpgraph.runComfyWorkflowPath` call, local-LLM-unload-before-generation, generated-image captioning via `withGeneratedImageDescriptions`, and ensuring the result lands in the owner's Storybook — moved verbatim into a `createComfyImageRunner(options)` factory. Its dependencies (`getNodes`, `connections`, `providerHealthById`, `llm`, `updateRuntimeNode`, `onComfyGenerationActive`, `signal`) are now parameters instead of closed-over graph-run locals. `resolveCreateImageCharacterByName`/`CreateImageCharacterNameResolution` moved with it.
2. **[src/graph/executeGraph.ts](../../src/graph/executeGraph.ts):** the closure is gone; `executeGraph` now just calls `createComfyImageRunner({ getNodes: () => nodes, connections, providerHealthById, llm: graphLlm, updateRuntimeNode, onComfyGenerationActive, signal })` — `nodes` is the exact same run-start snapshot the old inline closure captured, so behavior is byte-for-byte identical (confirmed by the pre-existing `structuredActions.spec.ts` image-generation case still passing unchanged, with no test edits). Re-exports `resolveCreateImageCharacterByName`/`CreateImageCharacterNameResolution` from the new file so `validation.fixtures.test.ts`'s existing import didn't need to change. A handful of now-dead imports (`localModelApi`, comfy default constants, `isLmStudioConnection`/etc., `isStorybookSourceNode`, `parseRpStorybookJson`/`rpStorybookJsonText`, `storybookCreateImageCharactersFromNodes`, `encodedDataUrlBytes`/`normalizeImageAttachment`, `withGeneratedImageDescriptions`) were removed; `isComfyImageConnection` was kept since it's still used elsewhere in the file for an unrelated purpose.
3. **[src/app/useGraphRun.ts](../../src/app/useGraphRun.ts):** `imageRunner` is now built eagerly at its declaration point via `createComfyImageRunner({ getNodes: () => nodesRef.current, connections, providerHealthById: providerHealthForRun, llm: nodeLlm.withAbortSignal(runSignal), updateRuntimeNode, onComfyGenerationActive: updateWorkflowComfyGenerationActive, signal: runSignal })`, instead of staying `undefined` until `executeGraph`'s `onImageRunnerReady` callback fires. For every protocol except staged, `executeGraph` still runs afterward and overwrites this with its own run-scoped instance — identical to prior behavior. For staged mode, which never reaches that call, this eager instance is what actually runs `image.generate`. No staged-workflow file (`recipeInventory.ts`, `stagedActionAdapter.ts`, `compileTurnPlan.ts`, `scheduler.ts`) needed to change — the compiler/recipe/adapter wiring for `image.generate` was already correct and had simply never had a working runner to call.

## A debugging note for whoever hits this pattern again

The Electron e2e suite (`test/e2e/*.spec.ts`) runs against the **built `dist/` bundle**, not live source (see `test/e2e/helpers.ts`'s `distIndex` check). `npm run build` must be rerun after every source change before the affected spec will reflect it — an initial debugging session on this task chased a phantom "the run just hangs" failure for a while before realizing the dist bundle was stale from before the `useGraphRun.ts` fix. Once rebuilt, the new spec passed on the first real attempt.
